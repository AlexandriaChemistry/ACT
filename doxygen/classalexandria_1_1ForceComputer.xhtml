alexandria::ForceComputer Class Reference

#include <act/forces/forcecomputer.h>

Description

Class to compute all the forces in a molecule or complex. It is imperative that there is only one force computer in each program, since results may depend on the flags given when initiating.

void setStallIterations (int n)
 Stop the shells of a fragment that make no progress Progress is a mean square force on the shells of at most half the last one that was. Shells that a strong field holds at the largest distance from their core can keep a force across the core-shell vector well above the tolerance, in a cycle or stuck, for as many steps as there are. A conformation that stops counts as not converged. In training, stopping after 3 steps gave clearly worse force fields, since many conformations that converge later stopped too, therefore no program uses this by default.
void setKeepShells (bool keep)
 Whether to start relaxing the shells from those of the previous relaxation In computeRelaxedEnergies the shells are still put on their parents for the energies before relaxation, from which the induction follows. The relaxation then starts from where the shells were relaxed the previous time, which needs far fewer iterations when the parameters changed little. The converged positions differ within the tolerance on the force, so a smaller tolerance is needed for the same precision.

◆ computeRelaxedEnergies()

void alexandria::ForceComputer::computeRelaxedEnergies ( MsgHandler * msghandler,
const ForceField * pd,
const std::vector< ACTMol * > & allmols,
bool resetShells,
bool separateInductionCorrection,
bool computeForces = true ) const

Compute energies and forces for monomers and/or dimers. Despite the name of the function it is possible to select RelaxShells::None which results in a single energy calculation. This will happen in case of a non-polarizable force field. Different molecules and conformation may take different number of iterations, but the intention of the code is to keep running just until the position of the selected shells have been minimized, or maxiter has been reached. The ACT energies are stored in the conformation data of the molecules, see ACTMol::conformationData, the energy maps of the conformations hold the QM energies.

Parameters
[in]msghandlerFor debugging and messages
[in]pdAn ACT force field
[in]allmolsThe molecules to compute
[in]resetShellsWhether or not to reset the shell positions before relaxation. This is an optimization that may or may not work.
[in]separateInductionCorrectionWhether or not to treat induction correction separately
[in]computeForcesWhether the forces are needed. If not, they are not computed and the forces of the conformations are not meaningful afterwards. Polarizable force fields always compute forces, since the shells are relaxed with them.

◆ setKeepShells()

void alexandria::ForceComputer::setKeepShells ( bool keep)
inline

Whether to start relaxing the shells from those of the previous relaxation In computeRelaxedEnergies the shells are still put on their parents for the energies before relaxation, from which the induction follows. The relaxation then starts from where the shells were relaxed the previous time, which needs far fewer iterations when the parameters changed little. The converged positions differ within the tolerance on the force, so a smaller tolerance is needed for the same precision.

Parameters
[in]keepWhether to keep the shells

◆ setStallIterations()

void alexandria::ForceComputer::setStallIterations ( int n)
inline

Stop the shells of a fragment that make no progress Progress is a mean square force on the shells of at most half the last one that was. Shells that a strong field holds at the largest distance from their core can keep a force across the core-shell vector well above the tolerance, in a cycle or stuck, for as many steps as there are. A conformation that stops counts as not converged. In training, stopping after 3 steps gave clearly worse force fields, since many conformations that converge later stopped too, therefore no program uses this by default.

Parameters
[in]nThe number of steps without halving the mean square force on the shells, 0 (the default) to relax until convergence or the maximum number of iterations
